# Stable SDK

`@stablechain/sdk` 是 Stable 的官方 TypeScript 客户端。它将 viem 封装成一个小型、类型化的 API，用于您最常进行的操作：转移 USDT0、跨链桥接、交换代币以及在 Stable 上赚取收益。路由、批准、小数位和链切换都已为您处理。

```ts
import { createStable, Network } from "@stablechain/sdk";
import { privateKeyToAccount } from "viem/accounts";

const stable = createStable({
  network: Network.Mainnet,
  account: privateKeyToAccount("0x..."),
});

const { txHash } = await stable.transfer({
  from: "0xYourAddress",
  to: "0xRecipient",
  amount: 10,
});
```

```text
txHash: 0x8f3a...2d41
```

## SDK 功能

- **`transfer`**：发送原生 USDT0 或 Stable 上的任何 ERC-20。Gas 费用自动以 USDT0 支付。
- **`quoteBridge` / `bridge`**：通过原生 USDT0 桥或 LI.FI 聚合器进行跨链转移。路由已为您选择，或您可以强制选择。批准和链切换在内部处理。
- **`quoteSwap` / `swap`**：在 Stable 的规范 Uniswap v3 部署上进行同链代币交换，内部处理滑点保护和 ERC-20 批准。无聚合器费用。
- **`earn`**：将 USDT0 存入 Morpho V2 金库以赚取收益，提现或赎回，并领取 Merkl 激励奖励。批准和适配器解除分配都已为您处理。
- **`createStableReader`**：一个只读客户端，用于获取金库 APY、您的头寸、收益预测和即时提款可行性检查。无需签名器。

SDK 已在 npm 上发布为 [`@stablechain/sdk`](https://www.npmjs.com/package/@stablechain/sdk)，并要求 `viem >= 2.0.0` 作为对等依赖。

## 两种桥接路线

:::note
原生 USDT0 路线已在 1.0.4 版本中实现。在此之前，所有桥接都通过 LI.FI 进行。
:::

`bridge` 直接使用原生 USDT0 路径。它调用源链上的 LayerZero 的 OFT 适配器，在该链上销毁 USDT0 并在目标链上铸造，因此您以 1:1 的比例收到全额，没有协议费用。您支付源链 gas 费用加上 LayerZero 消息传递费用，并等待 DVN 验证。LI.FI 路线是替代方案：它处理任何代币对并结算更快，但聚合器会收取费用。

默认情况下，SDK 会为您选择。当两条链都有 OFT 适配器且两侧的代币都是该链的 USDT0 时，它会使用 USDT0 路线，否则会回退到 LI.FI。设置 `route` 以覆盖：

```ts
import { Chain } from "@stablechain/sdk";

const { txHash } = await stable.bridge({
  fromChain: Chain.Ethereum,
  toChain: Chain.Stable,
  fromToken: "0x6C96dE32CEa08842dcc4058c14d3aaAD7Fa41dee", // USDT0 on Ethereum
  toToken: "0x779Ded0c9e1022225f8E0630b35a9b54bE713736", // USDT0 on Stable
  amount: 100,
  route: "usdt0",
});
```

```text
{ txHash: "0xabcd...7890", toAmount: 100 }
```

当代币对没有适配器时，强制使用 `"usdt0"` 会抛出 `StableValidationError`，而不是悄悄回退到收取费用的路线。当您需要速度或非 USDT0 代币时，强制使用 `"lifi"` 是一个紧急出口。有关每链支持表和报价返回的费用字段，请参阅 [SDK 参考](/cn/reference/sdk#bridgeroute)。

:::note
`Chain.Base` 和 `Chain.BSC` 没有 USDT0 OFT 适配器，因此它们总是通过 LI.FI 路由。USDT0 路由也是唯一在测试网上可用的路由，因为 LI.FI 只服务主网链。
:::

## 何时使用（以及何时不使用）

当您需要一个类型化、规范化的客户端，隐藏路由和批准样板时，请使用 SDK。当您需要直接控制交易构建、自定义 gas 策略或转移/桥接/交换之外的合约调用时，请回退到原始 viem 或 ethers。

:::note
SDK 使用任何兼容 viem 的签名器进行签名：私钥 `Account`、浏览器 `Transport`（如 `custom(window.ethereum)`）或预构建的 `WalletClient`（例如，wagmi 的 `useWalletClient` 返回的那个）。
:::
