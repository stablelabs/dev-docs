# 路线图

Stable 的三阶段路线图涵盖了共识、执行、存储、RPC 和 USDT 特有的流程。以下每个项目都标明了已上线、正在进行或已规划。

## 阶段 1：USDT 的基础层

状态：**主网已上线。**

### StableBFT：已上线

基于 CometBFT 构建的定制 PoS 共识协议。提供确定性终结和针对高达三分之一验证者数量的拜占庭容错能力。有关当前实现，请参阅[共识](/cn/explanation/consensus)。

### USDT0 作为原生 Gas：已上线

USDT0 是用于 Gas 支付和价值转移的原生资产，同时支持 ERC-20 接口 (`approve`、`transfer`、`transferFrom`、`permit`)。请参阅 [USDT0 作为 Gas](/cn/explanation/usdt-as-gas-token)。

### Stable Pay & Stable Name：正在进行中

Stable Pay 是一种 Web2.5 UX 钱包体验，旨在简化新用户的入门，同时兼容现有 Web3 钱包。Stable Name 是一种用户友好的别名系统，用人类可读的标识符替换原始 EVM 地址，用于发送和接收代币。

## 阶段 2：USDT 的体验层

状态：**v1.8.0 版本已在主网发布。**USDT 转账聚合器仍在开发中。

### MemIAVL 状态存储：v1.8.0 版本已上线

MemIAVL 用一个内存映射快照和仅追加的预写日志取代了 LevelDB。一个由 RocksDB 支持的 VersionDB 为比保留快照更早的历史查询提供服务。请参阅[存储 (StableDB)](/cn/explanation/stable-db)。

### 乐观并行执行：v1.8.0 版本已上线

Block-STM 在 CPU 核心之间并行执行事务，检测冲突，并重新执行受影响的工作。固定的区块内顺序保持了验证器之间确定性状态。请参阅[执行](/cn/explanation/execution)。

### 选择性 RecheckTx：v1.8.0 版本已上线

在区块提交后，节点仅重新检查受影响账户的待处理事务。当应用程序不支持时，CometBFT 会回退到完整的内存池重新检查。

### 2D 随机数和保证的区块空间：v1.8.0 版本已上线

独立的随机数通道可防止一个卡住的事务阻塞同一账户的所有后续事务。协议保留的随机数键识别企业流量，而每通道 Gas 配额保留区块容量。请参阅[保证的区块空间](/cn/explanation/guaranteed-blockspace)。

### USDT 转账聚合器：已规划

一种聚合机制，将 USDT0 转账分组并集体处理，从而降低每笔交易的开销并提高整体吞吐量。请参阅 [USDT 转账聚合器](/cn/explanation/usdt-transfer-aggregator)。

## 阶段 3：USDT 的全栈优化层

状态：**已规划。**

### StableBFT on Autobahn

基于 DAG 的 BFT 共识，自然地与 Stable 基于 CometBFT 的共识层集成。有关当前协议，请参阅 [StableBFT](/cn/explanation/consensus)，有关目标架构，请参阅 [Autobahn](/cn/explanation/autobahn)。内部概念验证已在受控环境中演示了超过 200,000 TPS（仅限共识）。

### StableVM++

高性能执行引擎，用 C++ 实现取代了基于 Go 的 EVM。预计可将 EVM 执行速度提高多达 6 倍。

### 高性能 RPC

一个完整的 RPC 堆栈，涵盖节点级增强（实时链状态处理）、节点集成索引（低延迟应用程序 API）、通过 WebSocket 进行可扩展的 pub/sub，以及按操作类型路由的混合负载均衡器。有关当前分流架构，请参阅[高性能 RPC](/cn/explanation/high-performance-rpc)。
